### **What is RAG (Retrieval-Augmented Generation)?**

Think of RAG as giving the AI an **open-book exam** instead of a closed-book one.

  * **Standard AI (Closed Book):** Relies only on what it was trained on (which might be outdated or vague).
  * **RAG (Open Book):** When you ask a question, the system first looks up the specific answer in your private library (e.g., historical letters, biographies), pastes that text into the prompt, and tells the AI: *"Using this specific text I just found, answer the user."*

For a history or relationship advice app, RAG is non-negotiable because it prevents **hallucinations**. It ensures the AI quotes *actual* advice from Nancy Reagan or Lady Bird Johnson, rather than making up generic platitudes.

-----

### **The Critical Step: Chunking**

**Chunking** is the process of breaking down your massive documents (books, letters, transcripts) into small, digestible pieces that the AI can search through.

If you paste an entire 500-page biography into the AI, it will be too expensive and the AI will get "lost" in the details. You need to feed it *only* the specific paragraph relevant to the user's question.

#### **How to Implement Chunking (Best Practices for History/Biographies)**

For your specific use case (historical figures and advice), do **not** use simple "fixed character" chunking (e.g., cutting every 500 words). This often slices sentences in half or separates a quote from its speaker.

Use **Semantic Chunking** with **Metadata**.

#### **1. The "Sliding Window" Strategy (The Basics)**

You break text into chunks of a set size (e.g., 500 tokens), but you include an **overlap** (e.g., 50 tokens).

  * **Why:** If a sentence gets cut off at the end of Chunk A, the overlap ensures it appears fully at the start of Chunk B. This preserves context.

#### **2. Semantic / Context-Aware Chunking (The Advanced Move)**

This is essential for history. You break the text based on natural pauses in the narrative.

  * **Split by Header:** If a book has a section titled *"1964 Campaign,"* that entire section should stay together if possible.
  * **Split by Paragraph:** Keep complete thoughts together.
  * **Split by Speaker:** If you are processing a transcript (e.g., LBJ tapes), **never** put LBJ's question and the other person's answer in different chunks. They must be glued together.

#### **3. The "Secret Sauce": Metadata Injection**

This is the most important part for your "Constitutional Network." A raw chunk of text is useless if the AI doesn't know *who* said it or *when*.

**Bad Chunk:**

> "I just want to go home and sit on the porch."

**Good Chunk (with Metadata):**

> **[Speaker: Lady Bird Johnson] [Year: 1964] [Context: Discussing LBJ's depression]**
> "I just want to go home and sit on the porch."

**Implementation:**
When you save the text to your Vector Database, you attach a JSON object to it:

```json
{
  "text": "I just want to go home...",
  "metadata": {
    "speaker": "Lady Bird Johnson",
    "year": 1964,
    "topic": "mental_health",
    "relationship_dynamic": "Anchor_vs_Hurricane"
  }
}
```

*Now, when a user asks "How did Lady Bird handle LBJ's depression?", your system can filter explicitly for that metadata.*

### **Python Script: Sliding Window Chunking**

```python
# pseudo_chunker.py

def create_sliding_chunks(text, chunk_size=200, overlap=50):
    """
    Splits text into chunks of 'chunk_size' words, 
    with an 'overlap' of words to preserve context.
    """
    # 1. Split the raw text into a list of individual words
    words = text.split()
    
    chunks = []
    
    # 2. Loop through the words, stepping forward by (chunk_size - overlap)
    #    This step calculation ensures the "slide" isn't a full jump.
    step = chunk_size - overlap
    
    for i in range(0, len(words), step):
        # 3. Create the current chunk
        #    Take words from index 'i' to 'i + chunk_size'
        chunk_words = words[i : i + chunk_size]
        
        # 4. Join words back into a string
        chunk_text = " ".join(chunk_words)
        
        # 5. Add to our list if it's not empty
        if chunk_text:
            chunks.append(chunk_text)
            
    return chunks

# --- EXAMPLE USAGE ---

# Sample text (Imagine this is from a biography of Lady Bird Johnson)
historical_text = """
The presidency is a heavy burden, but Lady Bird was the steel spine that kept Lyndon upright. 
Even when the polls crashed in 1968, she remained his primary political strategist. 
She famously told him, "You are as brave as any of the pioneers who first crossed this country." 
This statement wasn't just comfort; it was a strategic reminder of his identity. 
She knew that without his confidence, the administration would collapse.
"""

# Run the function
# We want chunks of 30 words, with 10 words overlapping.
my_chunks = create_sliding_chunks(historical_text, chunk_size=30, overlap=10)

# Print the results to see the overlap
for index, chunk in enumerate(my_chunks):
    print(f"--- CHUNK {index + 1} ---")
    print(chunk)
    print("\n")
```

### **Why This Works (The Logic)**

If you run this script, you will notice the **Overlap Effect**:

  * **Chunk 1** might end with: *"...pioneers who first crossed this country."*

By repeating that sentence, you ensure that if the AI retrieves **Chunk 2**, it still sees the full quote ("You are as brave...") rather than starting in the middle of a sentence like *"...this country. This statement wasn't just comfort..."*

### **Turning Text into "Embeddings" (Vectors)**

Once you have your text chunks (from the previous step), the next requirement is to convert them into **vectors**—lists of numbers that represent the *meaning* of the text.

This is the step that allows the AI to search by *concept* (e.g., matching "sadness" to "depression") rather than just matching exact keywords.

We will use OpenAI's `text-embedding-3-small` model, which is currently the industry standard for speed and cost.

### **The Python Script**

You will need the OpenAI library installed (`pip install openai`).

```python
import os
from openai import OpenAI

# 1. Initialize the client with your API Key
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

def get_embedding(text, model="text-embedding-3-small"):
    """
    Sends text to OpenAI and returns a list of float numbers (the vector).
    """
    # OpenAI requires newlines to be replaced to avoid tokenization errors
    text = text.replace("\n", " ")
    
    response = client.embeddings.create(
        input=[text], 
        model=model
    )
    
    # Extract the vector list from the response
    return response.data[0].embedding

# --- EXAMPLE WORKFLOW ---

# 2. Let's take the chunks we created in the previous step
chunks_to_process = [
    {
        "text": "The presidency is a heavy burden, but Lady Bird was the steel spine...",
        "metadata": {"speaker": "Lady Bird", "year": 1968}
    },
    {
        "text": "She famously told him, 'You are as brave as any of the pioneers'...",
        "metadata": {"speaker": "Lady Bird", "year": 1968}
    }
]

vectors_ready_for_db = []

print("Generating embeddings... this might take a moment.")

# 3. Loop through chunks and turn them into vectors
for item in chunks_to_process:
    # Call OpenAI
    vector = get_embedding(item["text"])
    
    # Create the final object for the database
    # It needs 3 things: ID, Vector, and Metadata
    db_record = {
        "id": f"doc_{item['metadata']['year']}_{len(vectors_ready_for_db)}",
        "values": vector,  # This is the list of numbers: [0.012, -0.231, ...]
        "metadata": {
            "text": item["text"], # Store the original text so you can retrieve it later!
            **item["metadata"]    # Merge in the speaker/year tags
        }
    }
    
    vectors_ready_for_db.append(db_record)

print(f"Successfully created {len(vectors_ready_for_db)} vector records.")
print(f"First vector length: {len(vectors_ready_for_db[0]['values'])}") 
# (Should be 1536 dimensions for this model)
```

1.  **The Model:** `text-embedding-3-small` is highly efficient. It outputs a vector with **1,536 dimensions** (a list of 1,536 numbers).

3.  **Storing the Text:** Notice inside `db_record` I stored the `text` inside the `metadata`.
      * **Crucial:** The Vector Database (Pinecone) uses the *vector* to find the match, but it returns the *metadata*. If you don't save the original text in the metadata, you will get a match but won't know what the text actually said\!

```typescript
import { Pinecone } from '@pinecone-database/pinecone';

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });
const pc = new Pinecone({ apiKey: process.env.PINECONE_API_KEY });

export async function POST(req: Request) {
  const { message } = await req.json();

  // 1. Turn user question into a vector

    topK: 3,
    includeMetadata: true
  });

  // 3. Extract the text from the top 3 matches
  const contextText = queryResponse.matches
    .map(match => match.metadata?.text)
    .join("\n\n");

  // 4. Send everything to GPT-4
  const completion = await openai.chat.completions.create({
    model: "gpt-4",

        If the answer isn't in the context, say you don't know.
        
        CONTEXT:
        ${contextText}`
      },
      { role: "user", content: message }
    ]
  });

  return NextResponse.json({ 
    response: completion.choices[0].message.content 
  });
```

```python
import os
import re
import fitz  # PyMuPDF
import psycopg2
from openai import OpenAI
from pgvector.psycopg2 import register_vector
from llama_index.core.node_parser import SentenceSplitter
from llama_index.core import Document

# --- CONFIGURATION ---
os.environ["OPENAI_API_KEY"] = "sk-..."
DB_CONNECTION = "dbname=mydb user=myuser password=mypass host=localhost"

client = OpenAI()

def run_pipeline(pdf_path):
    print(f"--- Processing: {pdf_path} ---")

    # =========================================================
    # STEP 1: INGEST (Read PDF)
    # =========================================================
    doc = fitz.open(pdf_path)
    raw_text = ""
    for page in doc:
        raw_text += page.get_text()
    
    print(f"1. Ingested {len(raw_text)} characters.")

    # =========================================================
    # STEP 2: CLEAN (Remove Artifacts)
    # =========================================================
    def clean_text(text):
        # Remove page numbers (e.g., "Page 12" or just "12" at start/end of lines)
        text = re.sub(r'\n\s*\d+\s*\n', '\n', text)
        # Remove headers/footers (basic heuristic: widely spaced all-caps)
        text = re.sub(r'\n\s*[A-Z\s]{5,}\s*\n', '\n', text)
        # Collapse multiple spaces/newlines
        text = re.sub(r'\s+', ' ', text).strip()
        return text

    clean_content = clean_text(raw_text)
    print("2. Text cleaned.")

    # =========================================================
    # STEP 3: CHUNK (LlamaIndex Splitter)
    # =========================================================
    # Split by paragraph/sentence with overlap
    splitter = SentenceSplitter(
        chunk_size=1024,    # Tokens (approx)
        chunk_overlap=200   # 20% overlap
    )
    
    # LlamaIndex expects a 'Document' object
    llama_doc = Document(text=clean_content)
    nodes = splitter.get_nodes_from_documents([llama_doc])
    
    chunks = [node.text for node in nodes]
    print(f"3. Split into {len(chunks)} chunks.")

    # =========================================================
    # STEP 4: ENRICH (Tagging with GPT-4o-mini)
    # =========================================================
    enriched_data = []
    
    print("4. Enriching chunks (this may take a moment)...")
    for i, chunk_text in enumerate(chunks):
        # Generate metadata/tags
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {"role": "system", "content": "You are a librarian. Analyze the following text chunk. Return ONLY a JSON object with these keys: 'topic' (2-3 words), 'sentiment' (positive/negative/neutral), and 'entities' (list of people/places)."},
                {"role": "user", "content": chunk_text[:2000]} # Send first 2k chars to save cost if chunk is huge
            ],
            response_format={"type": "json_object"}
        )
        metadata = response.choices[0].message.content
        
        # Generate Embedding (Vector) for the text
        emb_response = client.embeddings.create(
            input=chunk_text,
            model="text-embedding-3-small"
        )
        vector = emb_response.data[0].embedding
        
        enriched_data.append({
            "chunk_text": chunk_text,
            "vector": vector,
            "metadata": metadata
        })

    # =========================================================
    # STEP 5: STORE (pgvector)
    # =========================================================
    conn = psycopg2.connect(DB_CONNECTION)
    
    # Ensure pgvector extension is enabled
    cur = conn.cursor()
    cur.execute("CREATE EXTENSION IF NOT EXISTS vector")
    register_vector(conn)
    
    # Create table if not exists
    cur.execute("""
        CREATE TABLE IF NOT EXISTS historical_docs (
            id SERIAL PRIMARY KEY,
            content TEXT,
            metadata JSONB,
            embedding vector(1536)
        );
    """)
    
    # Insert data
    for item in enriched_data:
        cur.execute(
            "INSERT INTO historical_docs (content, metadata, embedding) VALUES (%s, %s, %s)",
            (item["chunk_text"], item["metadata"], item["vector"])
        )
    
    conn.commit()
    cur.close()
    conn.close()
    print(f"5. Saved {len(enriched_data)} records to pgvector.")
```

### **The Neo4j Injection Code**

Add this function to your existing pipeline. It takes the `enriched_data` (from Step 4) and pushes it into the graph.

```python
import json
from neo4j import GraphDatabase

# --- CONFIGURATION ---
NEO4J_URI = "bolt://localhost:7687"
NEO4J_USER = "neo4j"
NEO4J_PASSWORD = "your_password"

def store_in_neo4j(enriched_data):
    driver = GraphDatabase.driver(NEO4J_URI, auth=(NEO4J_USER, NEO4J_PASSWORD))
    
    print(f"--- Storing {len(enriched_data)} chunks in Neo4j ---")

    # Cypher query to create the graph structure
    # We use MERGE to ensure we don't create duplicate People/Topics
    cypher_query = """
    // 1. Create the Chunk node
    MERGE (c:Chunk {text_hash: $chunk_hash})
    SET c.text = $text,
        c.sentiment = $sentiment,
        c.year = $year

    // 2. Link Chunk to the Speaker (e.g., Lady Bird)
    MERGE (s:Person {name: $speaker})
    MERGE (s)-[:SPOKE]->(c)

    // 3. Link Chunk to Topics (e.g., "Loyalty", "War")
    FOREACH (topic_name IN $topics |
        MERGE (t:Topic {name: topic_name})
        MERGE (c)-[:DISCUSSES]->(t)
    )

    // 4. Link Chunk to Mentioned Entities (e.g., "JFK", "Vietnam")
    FOREACH (entity_name IN $entities |
        MERGE (e:Entity {name: entity_name})
        MERGE (c)-[:MENTIONS]->(e)
    )
    """

    with driver.session() as session:
        for item in enriched_data:
            # Parse the JSON metadata generated by GPT-4o-mini
            # Expected format: {"topic": ["Loyalty"], "entities": ["JFK"], "sentiment": "positive"}
            meta = json.loads(item["metadata"])
            
            # Create a simple hash for ID (or use a UUID)
            chunk_hash = str(hash(item["chunk_text"]))
            
            session.run(cypher_query, 
                chunk_hash=chunk_hash,
```

```python
from neo4j import GraphDatabase

# Initialize Driver
driver = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j", "your_password"))

def get_topic_context(topic_name):
    """
    Retrieves a chronological history of a specific topic from the Graph.
    """
    query = """
    MATCH (t:Topic {name: $topic})<-[:DISCUSSES]-(c:Chunk)<-[:SPOKE]-(p:Person)
    OPTIONAL MATCH (c)-[:MENTIONS]->(e:Entity)
    RETURN 
        p.name AS Speaker,
        c.year AS Year,
        c.text AS Text,
        collect(e.name) AS Entities
    ORDER BY c.year ASC
    LIMIT 5

                f"Related Context: {entities}\n"
                f"Quote: \"{record['Text']}\"\n"
            )
```
